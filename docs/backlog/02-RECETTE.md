# Recette fonctionnelle du code existant — backlog opérationnel

**Arbitrage du 21/11/2026 :** les cartes exigeant le **microphone physique local du PC**, **Twitch** ou **OBS** sont suspendues en `Bloqué` jusqu'à nouvel ordre. Ce n'est **pas** une suspension générale des travaux sur Windows ni des tests Discord/Android/mémoire. Les sous-tests indépendants restent possibles, mais les cartes mixtes ne sont pas closes. [Passation](../operations/handoffs/2026-11-21-chatgpt-suspension-micro-twitch-obs.md).

**Branche :** develop · **Révision :** 21 novembre 2026 · **Type :** REC · **État de référence :** lecture GitHub, pas recette locale.

Ces tâches vérifient sur appareils et services réels des fonctionnalités déjà codées. Elles ne doivent jamais être transformées en développement à refaire par défaut. Une anomalie reproductible génère une carte DEV liée.

**Livraison de la PR #38 sur `develop` le 22/11/2026 :** sept suivis déplacés de DEV vers REC-031 à REC-037. **Après validation du propriétaire le même jour : REC-031, REC-032, REC-033 et REC-034 sont Done ; REC-035, REC-036 et REC-037 demeurent À valider.** Les réserves fonctionnelles de REC-033 sont **acceptées pour cette version, non corrigées** ; REC-035 conserve sa réserve et REC-037 attend la configuration et les essais Windows/Android.

**Règle validée le 21/11/2026 :** tout suivi de fonctionnalité `À valider` est une unique carte `REC`, sans doublon de suivi DEV/REC. Transferts historiques : `DEV-011 → REC-026`, `DEV-015 → REC-027`, `DEV-016 → REC-028`, `DEV-017 → REC-029`, `DEV-018 → REC-030`. Les résultats de tests et réserves sont conservés.

**Règle de tri au 21/11/2026 :** les scénarios automatisables restent `À faire` ou `En cours` tant qu'un agent n'a pas exécuté les tests et apporté leurs preuves. Les recettes qui ne peuvent pas être exécutées automatiquement dans l'environnement autorisé sont **directement `À valider`**, pour réalisation et décision par un humain sur les scénarios indiqués. `À valider` n'indique pas que le test manuel a réussi, et ne dispense ni des essais automatisables complémentaires ni des critères de clôture. Si le scénario est réellement empêché par un prérequis, le signaler comme `Bloqué` plutôt que d'affirmer un succès.

Les priorités expriment la valeur de livraison et les dépendances, non un ordre absolu de traitement. **Responsable pressenti :** Codex (modèle ou sous-agent disponible) pour la réalisation sur PC, propriétaire pour les autorisations/comptes et, s'il le souhaite, la validation ; attribution effective à confirmer. **La [DoD officielle](DEFINITION_OF_DONE.md) exige la réalisation, les tests pertinents, l'intégration applicable, la traçabilité et la validation par Codex OU par le propriétaire.** La validation humaine n'est pas obligatoire.
